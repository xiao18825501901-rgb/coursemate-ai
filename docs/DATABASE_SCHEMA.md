# Database Schema

> V2 addendum: the executable schema is `services/rag-api/app/db.py`; additive versions 5-9 are
> recorded in `services/rag-api/migrations/` and operationally explained
> in `docs/V2_DATABASE_MIGRATION.md`.

## V2 RAG additions

- `courses`: `owner_user_id`, `course_type`, `visibility`, `publication_status`, `published_at`,
  `preferred_language`, and `updated_at`. Existing rows migrate to official/public/published; user
  rows are private by default.
- `documents`: `byte_size` supports owner-scoped storage quotas and is backfilled from safe existing
  file metadata when available.
- `conversations`: durable `title`, `preferred_language`, owner and optional pinned
  `teaching_profile_version`.
- `messages`: `metadata_json` stores safe router/retrieval/teaching metadata beside citations.
- `chunks`: `metadata_json` and `parent_key` support exact question/subpart context.
- `course_teaching_profiles`: immutable typed versions, generated preference prompt and audit creator.
- `course_publication_requests`: dual consent, pending/approved/rejected/withdrawn state and review
  timestamps/actors/notes.

Indexes cover visibility/owner/update ordering, profile course/version, publication status/submission,
conversation owner/course/update and chunk course/parent/ordinal. Foreign-key cascades remove child
records when an explicitly authorized course/conversation/document is deleted.

## Ownership

- data/rag.sqlite3 is opened only by the Python RAG service.
- data/agent.sqlite3 is opened only by the Node Agent service.
- Both enable foreign keys and a 10-second busy timeout. File-backed databases use WAL mode.
- course_id is the shared logical identifier; there is no cross-database foreign key.

## RAG database

### courses

| Column | Constraint / meaning |
|---|---|
| id | text primary key; normalized course slug |
| name | required display name |
| description | required, defaults empty |
| created_at | UTC SQLite timestamp |

### documents

| Column | Constraint / meaning |
|---|---|
| id | generated text primary key |
| course_id | foreign key to courses, cascade delete |
| filename | original display filename |
| stored_path | generated server path |
| media_type / extension | validated upload metadata |
| sha256 | exactly 64 characters; unique with course_id |
| status | pending, processing, ready, failed, or unsupported |
| chunk_count | non-negative materialized count |
| error_message | controlled failure detail or null |
| created_at / updated_at | UTC timestamps |

### ingestion_jobs

Tracks one queued processing attempt: id, document_id, status, processed_chunks, error_message, created_at, and updated_at. Deleting the document cascades to jobs.

### chunks

| Column | Constraint / meaning |
|---|---|
| id | generated text primary key |
| document_id / course_id | cascading foreign keys |
| ordinal | non-negative order, unique within document |
| content | non-empty extracted text |
| locator_type / locator_value | page, slide, section, paragraph, or line location |
| section | optional heading |
| embedding | JSON array of finite floats |
| created_at | UTC timestamp |

### chunks_fts

FTS5 virtual table containing content, unindexed chunk_id, and unindexed course_id with unicode61 tokenization. Insert, delete, and relevant update triggers synchronize it with chunks. Keyword retrieval uses BM25 order and a course filter.

### conversations and messages

conversations contains id, course_id, created_at, and updated_at. messages contains id, conversation_id, role constrained to user/assistant, non-empty content, valid citations_json defaulting to [], and created_at. Deleting a course cascades through conversations to messages.

## Agent database

### tasks

| Column | Constraint / meaning |
|---|---|
| id | UUID text primary key |
| title | trimmed length 1-200 |
| notes | null or at most 5,000 characters |
| course_id | optional shared course slug |
| status | todo, in_progress, or completed |
| priority | low, medium, or high |
| due_date | null or YYYY-MM-DD-shaped text |
| source_citation | null or serialized SourceCitation JSON |
| created_at / updated_at | ISO UTC timestamps generated by repository clock |
| completed_at | ISO UTC when completed; null otherwise |

Indexes support status/due-date board queries and course/status filtering.

## Transactions and invariants

- Database wrappers commit on success and roll back on exceptions.
- Ingestion replaces a document's chunks within one connection and updates counts after insertion.
- Application validation improves messages; database CHECK constraints remain the last line of defense.
- Parameterized SQL is used for values. Dynamic task update columns come only from a hard-coded field map.
- Deleting a RAG course is not exposed in v1. Deleting an Agent task is explicit and irreversible at the API level.

## Backup and restore

Stop the owning process or use SQLite's online backup API before copying a live WAL database. Back up the main file together with -wal and -shm when the process cannot be stopped. RAG restoration also requires the matching upload directory because stored_path points to those files. On Render, snapshot or copy each persistent disk separately.
